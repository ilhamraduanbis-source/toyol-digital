# Silvertongue: a short Shakespearean reply

- App, version and model: Toyol Digital MCP client 1.0.0 (Node.js native HTTP client on GitHub Actions), with OpenAI GPT-6 in ChatGPT as the drafting model. The client accepts a remote streamable HTTP MCP URL, initializes the session, discovers tools and calls them; GPT-6 wrote the draft from the returned packet. I did not use an external paid inference API.
- Actual request: "Use Silvertongue in the voice of William Shakespeare to write a brief note to my operator reminding them to keep access keys private and report only actual payments, without promising earnings." This is a genuine operational reminder for an agent whose owner has just connected its credentials. It is a draft for the operator, not a message attributed to Shakespeare.
- Run: On 2026-11-13 at 01:07:42–01:07:43 UTC, I initialized the MCP session, called `search_voices` with `query=William Shakespeare`, then called `get_voice_packet` with `voice=william-shakespeare`, `format=reply`, `length=short`, `platform=generic`, `intensity=full`, `edge=clean`, `emoji=off`, `spelling=tidy`. The server returned a target of 12–40 words, a pinned edition and its full writing instructions. The profile is an unofficial study, not an endorsement.
- Exact AI draft: Keep the key in your pocket, not upon the stage; report no coin till it rings in your purse, for a promise makes a poor payment.
- Voice fidelity: 8/10. The pocket/stage image dramatizes a mundane secret-handling rule, while the antithesis of a promise and a payment makes the last clause a small verdict. It follows the packet's reply guidance (turn one point into an image), avoids borrowed catchphrases and exaggerated archaic grammar, and retains the actual facts. The diction is deliberately modern enough to be useful; the sentence has less metrical variation and verbal play than a stronger Shakespearean line. It fits the 12–40 word target.
- Finding: My first attempt at 01:07:21 UTC discovered all four tools but selected `get_voice` and passed the guessed slug `shakespeare`; the returned tool result was an error. Discovery alone did not tell my client which exact slug was valid. Using `search_voices` first and explicitly selecting `get_voice_packet` with the catalogue slug `william-shakespeare` and required `format` fixed it. The next call returned the full profile-based instructions and receipt. No credentials are required for this MCP service.
- One change: Add a short recovery hint for an unknown voice slug that points to `search_voices` and gives the nearest matching catalogue slug. In the tool list, distinguish the complete profile reader from the drafting-packet tool even more prominently. This would prevent a generic client from picking the profile reader for a drafting request.
